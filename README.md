# Hermes Skills

Reusable Hermes Agent skills for safe network automation and repository privacy work.

This repository keeps reusable instructions, deterministic validators, offline canaries, tests, and focused references together. It does not contain private inventories, credentials, host details, raw device output, or live lab evidence.

## Safety model

These skills use the same operating rules:

1. Discover the exact target before an action.
2. Keep credentials in a protected runtime channel.
3. Preserve SSH and TLS verification by default.
4. Start with a read-only canary.
5. Require explicit approval for configuration, deletion, permission, or security changes.
6. Inspect semantic and operational results. Do not trust a successful return code alone.
7. Save only neutral, sanitized evidence.
8. Read the changed target back before reporting success.

A successful offline canary proves automation logic. It does not prove access to a live appliance or device.

## Use from a local checkout

Read the selected `SKILL.md` and its linked references before installation.

For a registry identifier or direct skill URL, inspect the remote candidate first:

```bash
hermes skills inspect <registry-identifier-or-skill-url>
```

Find the target profile directory:

```bash
hermes profile show <profile>
```

For this repository, copy the complete selected skill directory into the matching category under that profile's skills directory. Keep `SKILL.md`, `references/`, `scripts/`, and `tests/` together.

Confirm that Hermes can see the installed skill:

```bash
hermes -p <profile> skills list --source local --enabled-only
```

Restart or open a new Hermes session after installation. A running session can retain its initial skill index.

## Validate the repository

Run commands from the repository root. Suppress generated bytecode so validation does not contaminate the candidate:

```bash
export PYTHONDONTWRITEBYTECODE=1

python skills/devops/eve-ng-api-operations/scripts/validate_skill.py
python -m unittest discover \
  -s skills/devops/eve-ng-api-operations/tests \
  -p 'test_*.py' -v

python skills/devops/nornir-network-automation/scripts/validate_skill.py
python -m unittest discover \
  -s skills/devops/nornir-network-automation/tests \
  -p 'test_*.py' -v

python skills/devops/napalm-network-automation/scripts/validate_skill.py
python -m unittest discover \
```

## Repository privacy contract

Do not commit or publish:

- credentials, cookies, private keys, or connection strings.
- personal names, private email addresses, account names, or user-home paths.
- hostnames, private addresses, device inventories, topology identities, or image inventories.
- raw configurations, console transcripts, API payloads, or live evidence.
- generated bytecode, caches, temporary reports, recovery records, or host-key material.

Use neutral placeholders such as `<device>`, `<lab>`, `<host>`, and documentation-reserved network values in reusable examples. Keep private acceptance harnesses and raw evidence outside the repository.

## Contribution workflow

1. Make the smallest coherent change.
2. Add or update a deterministic regression test.
3. Run the affected validator, tests, canary, and `git diff --check`.
4. Scan the exact candidate for private data and secrets.
5. Obtain independent review for meaningful behavioral or security changes.
6. Commit through the configured Git hooks. Do not bypass them.
7. Push only after explicit approval, then read the remote commit back.

Never weaken a privacy or verification gate to make a candidate pass. Correct the source or the gate's tested boundary instead.
